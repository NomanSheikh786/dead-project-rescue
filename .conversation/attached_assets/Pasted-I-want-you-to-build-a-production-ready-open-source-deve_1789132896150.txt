I want you to build a production-ready open-source developer tool called **DeadProject Rescue**.

## Core Idea

DeadProject Rescue takes an old or abandoned GitHub repository, ideally 2–5+ years old, analyzes its dependencies and codebase, identifies outdated or incompatible packages, upgrades the project to modern versions, fixes breaking changes where possible, and prepares a clean migration Pull Request.

The initial focus should be JavaScript and TypeScript projects using:

* Node.js
* React
* Next.js
* Express
* TypeScript
* npm
* yarn
* pnpm

The tool should be designed so more ecosystems can be supported later.

---

## Main User Flow

A user provides a GitHub repository URL such as:

https://github.com/example/old-react-project

The application should:

1. Clone or securely inspect the repository.
2. Detect the project type automatically.
3. Read:

   * package.json
   * package-lock.json
   * yarn.lock
   * pnpm-lock.yaml
   * tsconfig.json
   * next.config.*
   * eslint config
   * babel config
   * Node version files
   * GitHub Actions workflows
4. Detect outdated dependencies.
5. Identify deprecated packages.
6. Detect dependency conflicts.
7. Determine the current Node.js version requirements.
8. Detect framework versions such as React and Next.js.
9. Generate a migration plan.
10. Upgrade dependencies in controlled stages.
11. Apply automated code migrations where possible.
12. Run:

* install
* lint
* type checking
* build
* tests

13. Detect failures after each upgrade.
14. Attempt to fix common migration problems automatically.
15. Generate a migration report.
16. Produce a Git diff.
17. Prepare a GitHub Pull Request containing all changes.

# Example

Old repository:

Node.js 14
React 17
Next.js 11
TypeScript 4
ESLint 7

DeadProject Rescue may recommend:

Node.js 22 LTS or the latest suitable LTS version
React 19 if compatible
Current stable Next.js version if migration is safe
Modern TypeScript
Modern ESLint configuration

Do NOT blindly upgrade everything to the newest version.

The tool must evaluate compatibility first.

# Migration Strategy

Use staged migrations instead of one massive upgrade.

Example:

Stage 1:
Update Node runtime and tooling.

Stage 2:
Update safe patch and minor dependencies.

Stage 3:
Upgrade React.

Stage 4:
Upgrade Next.js.

Stage 5:
Upgrade TypeScript and ESLint.

Stage 6:
Fix breaking API changes.

Stage 7:
Run validation.

Every stage should create a clear log.

If an upgrade is considered too risky, mark it as:

MANUAL REVIEW REQUIRED

instead of breaking the repository.

MEDIUM
HIGH

Evaluate risk using factors such as:

* major version jumps
* deprecated packages
* peer dependency conflicts
* Node engine compatibility
* framework compatibility
* number of dependent packages
* config changes
* known breaking changes
* unavailable replacement packages

# Automated Code Fixes

Implement a migration engine capable of applying code transformations.

Possible technologies:

* AST parsing
* jscodeshift
* ts-morph
* Babel parser
* recast

Do not rely only on regex for source code transformations.

Possible automated fixes:

* deprecated React APIs
* old Next.js configuration
* CommonJS to ESM where appropriate
* outdated imports
* ESLint configuration migration
* TypeScript configuration updates
* Node API replacements
* deprecated package replacements

Design migrations as individual codemods.

Example:

migrations/
react/
next/
node/
typescript/
eslint/

Each migration should be independently testable.

# Security

Security is extremely important.

Never execute untrusted repository code directly on the main server.

Run repository analysis and build commands inside an isolated environment.

Recommended options:

* Docker containers
* ephemeral sandboxes
* resource limits
* timeout limits
* disabled privileged mode
* restricted filesystem
* controlled network access

Protect against:

* malicious npm scripts
* crypto miners
* fork bombs
* filesystem attacks
* secret stealing
* arbitrary shell commands

Package install scripts should be treated as untrusted.

Design the execution architecture accordingly.
